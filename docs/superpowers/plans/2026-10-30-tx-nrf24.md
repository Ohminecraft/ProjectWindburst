# Tay phát DIY + receiver nRF24 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A DIY transmitter firmware (ESP32-C5, 2 joysticks, nRF24) that flies a Windburst flight controller through an nRF24 receiver on the FC's second SPI bus, configured from the same app (which shows only TX tabs when a TX is plugged in).

**Architecture:** One portable nRF24 register driver (`src/hal/radio/nrf24.h`) behind a tiny bus interface, used by both ends; one portable link layer (`src/radio/wb_radio.h`: packets, CRC, sequence, bind) shared by TX and RX. The FC side is a new receiver kind inside `RcReceiver` (so `FlightApp` keeps treating it like CRSF); the TX side is a portable `TxApp` (sticks → channels → link, WBP host) with a thin ESP32-C5 `main_tx.cpp`. On the PC a register-level nRF24 simulator plus a simulated "air" joins a virtual TX to the FC's `VirtualBoard`, for FIL tests and for `wb_sim`.

**Tech Stack:** C++17 header-only firmware (Arduino-ESP32 3.3 / pioarduino), PC tests (`make test`, FIL in `test_fw`), WBP schema + `tools/gen_proto.py`, Python app (`app/wbclient`, vanilla JS pages, pytest + playwright), `tools/mutate.py`.

**Spec:** `docs/superpowers/specs/2026-10-30-tx-nrf24-design.md`

## Global Constraints

- Schema: edit `protocol/wbp_schema.json`, run `python tools/gen_proto.py`; enums append-only; new sections get new ids; new fields only at the end of a section, and a grown section gets its old size in `compat` (max 4 entries, newest first; drop the oldest if full).
- Code comments in English, docs in Vietnamese, user-facing app text in Vietnamese with an `en.js` entry (`app/tests/test_gui_i18n.py` must pass). Keep each file's line endings (`todo.txt`, `test/test_core.cpp` are CRLF).
- nRF24 defaults (spec 4.1): 250 kbps, power MAX, 100 packets/s; choices 250k/1M/2M, MIN/LOW/HIGH/MAX, 50/100/150 packets/s (150 only where the airtime check of Task 2 says it fits). Hardware CRC16, auto-ACK, dynamic payload, ACK payload on both ends.
- Bind (spec 4.2): random 5-byte address + RF channel made by the TX; fixed bind address `{0x57,0x42,0x4E,0x44,0x21}` ("WBND!"), bind RF channel 100, power MIN while binding; FC listens for bind for 60 s after boot only while never bound; never bind while armed.
- At least 8 channels at ≥ 10 bits, 1000..2000 µs; AUX channels without a source = 1000; no "armed" bit in the packet.
- TX throttle modes (spec 5): `ALTPOS` = direct (centre 1500); `MANUAL` = accumulating, starts at 1000 whenever the drone is not armed or no telemetry; mode is a TX setting. Default `MANUAL` (my call: the safe one when nobody has chosen).
- TX default pins (old project `src/common/pins.h`): joy1 X/Y = GPIO4/5, joy2 X/Y = GPIO3/2, nRF MISO 6, SCK 7, MOSI 8, CE 23, CSN 24. Default stick map: roll = joy1 X, pitch = joy1 Y, throttle = joy2 Y, yaw = joy2 X.
- The nRF24 driver runs in the FC's sensor thread (`slow_update`), never in `flight_cycle`; it never busy-waits on the radio.
- Not in this plan: STM32 receiver, frequency hopping, OLED / LED / switches / battery on the TX.
- Version: FC **0.38.0** (`src/config/version.h`, the "Windburst RX (sim) 0.38.0" string in `test/test_fw.cpp`); the TX reports the same version numbers with the name "Windburst TX".
- Windows build: `export PATH=/c/msys64/ucrt64/bin:$PATH; mingw32-make -k build/test_X` (the Makefile adds `-D_USE_MATH_DEFINES`); PlatformIO: `~/.platformio/penv/Scripts/pio.exe run -e rx_esp32_s3 -e rx_f405 -e tx_c5`.
- Every feature: unit + FIL + app tests, docs, HANDOFF row, `todo.txt` (Cần test + Hoàn Thành), mutants. Never edit `src/` or `test/` while `tools/mutate.py` runs. Do not commit — the user commits (the "Commit" steps below are checkpoints: run the listed tests, nothing else).

## Review Focus

1. **A second Windburst pair switched on nearby** — expectation: neither FC moves for the other's TX. Test in Task 7 (`two_pairs_do_not_hear_each_other`).
2. **TX in MANUAL throttle, armed by the stick gesture, sticks released** — expectation: throttle channel stays ≤ 1050, the craft stays on the ground. Test in Task 7 (`manual_throttle_release_after_arm_stays_down`).
3. **Radio goes quiet in flight (TX off / out of range)** — expectation: FC `linkOk` false after `receiver.rx_timeout_ms`, failsafe as with CRSF; back on → failsafe ends after the FC's own recovery rules. Test in Task 7.
4. **A corrupted / replayed / out-of-range packet** — expectation: dropped whole, channels unchanged; a damaged or out-of-range one is counted in `bad_frames`, a replay / duplicate (a retransmission whose ACK was lost - normal radio traffic) is dropped without counting. Tests in Task 3 and Task 5.
5. **The nRF24 bus is already taken (SD card on SPI, PMW3901, LED strip) or pins not set** — expectation: receiver does not start, boot report says why, nothing else breaks. Test in Task 6.

### Task 3: Link packets (shared TX / RX)

**Files:**
- Create: `src/radio/wb_radio.h`; Test: `test/test_radio.cpp`

**Interfaces:**
- Consumes: `rx::crc8_dvb_s2` (`src/hal/rx/rx_proto.h`).
- Produces (namespace `wbr`), every packet ends with CRC8 DVB-S2 over all previous bytes:
  - Control `0x01`: `[type][seq u8][8 × 10-bit channels, value = µs − 1000 (0..1000), packed little-endian bit order][crc]` = 13 bytes. `uint8_t encode_control(uint8_t seq, const uint16_t ch_us[8], uint8_t out[32])`; `bool decode_control(const uint8_t*, uint8_t n, uint8_t& seq, uint16_t ch_us[8])` (false: bad length, CRC, a value > 1000).
  - Bind `0x02`: `[type][addr 5][rf_channel][rate][pps][crc]`; Bind-ack (ACK payload) `0x82`: `[type][addr 5][crc]` (echo of the address = "I took it").
  - Radio config `0x03`: `[type][seq][rf_channel][rate][pps][crc]` (sent on the old settings; the FC switches after it ACKs; the TX switches after its ACK).
  - Telemetry (ACK payload) `0x81`: `[type][flags: bit0 armed, bit1 failsafe][mode fly_mode][batt_cv u16][lq u8][crc]` = 7 bytes.
  - `class SeqFilter { bool accept(uint8_t seq, uint32_t now_ms, uint16_t timeout_ms); uint32_t lost() const; }` — accepts a newer sequence (`(int8_t)(seq - last) > 0`), drops equal/older (a retransmitted copy whose ACK was lost), counts gaps as lost, accepts anything after `timeout_ms` of silence.
  - `void make_address(uint32_t r0, uint32_t r1, uint8_t addr[5])` — from two random words; no byte 0x00, 0x55, 0xAA, 0xFF in the first byte (preamble-like), never the bind address.
  - Constants `kBindAddr[5]`, `kBindChannel = 100`.
